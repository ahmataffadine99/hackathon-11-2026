# Exercice 10 : asynchronisme

> **État :** référence TypeScript vérifiée ; intégration Go en attente de P2 et P4.

## Problème étudié

Source : [`projects/10`](../../projects/10). Trois calculs peuvent échouer ;
`rightAsyncPipe` compose leurs étapes, `asyncGroup` regroupe les résultats et
`DCommon.asyncPipe` applique la conversion des valeurs. Le point essentiel est
l'ordre séquentiel des appels et l'arrêt au premier `Left`.

Sortie TypeScript observée :

```text
[ 'transaction annulée' ]
```

## Stratégie

L'option A d'[ADR-5](../decisions/ADR-5-async.md) traduit les pipelines comme des
appels Go synchrones séquentiels. `rightAsyncPipe` réutilise le handler de
`rightPipe`; `asyncGroup` appelle chaque fabrique dans la boucle, avant de
continuer uniquement si le résultat est Right ; `DCommon.asyncPipe` réutilise
le handler de `pipe`. Les fabriques ne sont pas appelées en avance, ce qui
préserve l'arrêt au premier `Left`.

La forme tableau d'`asyncGroup` est prise en charge. La forme objet est refusée
explicitement. Aucun goroutine ni channel n'est produit.

## Go produit

**Pas encore observé.** Sur cette branche, `pnpm build:10` échoue avant de
générer le Go, avec `notfound-transformer` pour le type `DisplayError`.
L'intégration de P4 (`Promise<T>`) et de P2 (`async`/`await`) est nécessaire
avant de publier un extrait Go, de lancer `go vet` et de comparer les sorties.

## Variantes

Voir [`variations/README.md`](../../variations/README.md) :
`10-group-lazy-stop`, `10-right-async-pipe-left`, `10-async-pipe-plain`,
`10-await-direct` et `10-sync-between`.

Les cinq sources passent `tsc --noEmit` puis `tsx`. `10-sync-between` est un
écart attendu : JavaScript affiche l'effet synchrone intercalé avant les
fabriques, tandis que l'option A les exécute dans l'appel Go inliné.

## Limites et validation restante

- La comparaison TypeScript/Go, `go vet`, l'analyse `-gcflags=-m` et les mesures
  de l'exercice 10 restent à effectuer après l'intégration de P2 et P4.
- L'option A ne reproduit pas l'intercalage des microtâches avec du code
  synchrone et n'est pas un modèle général des E/S asynchrones.
- L'objet `asyncGroup` est hors périmètre et refusé explicitement.

## Reproduire

```bash
pnpm exec tsc --noEmit -p variations/10-group-lazy-stop/tsconfig.json
pnpm exec tsx --tsconfig variations/10-group-lazy-stop/tsconfig.json variations/10-group-lazy-stop/index.ts
pnpm build:10
```
