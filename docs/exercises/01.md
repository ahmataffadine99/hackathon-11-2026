## Problèmes étudiés

Source : [`projects/01`](../../projects/01).

```ts
// add.ts
export function add(one: number, two: number): (
	| DEither.Success<number>
	| DEither.Fail
) {
	return DEither.success(one + two);
}

// index.ts
const result = add(1, 2);

if (DEither.isRight(result)) {
	DCommon.print(result);
}
```

## Stratégie

> Décidée au point d'équipe du Sprint 0 (`PLAN_HACKATHON.md` §0 et §8, contrat d'interface Go). **À compléter après merge** avec les choix effectivement implémentés.

| Problème | Traduction Go visée |
|---|---|
| P1 type | `Success<number> \| Fail` donne **`shard_dependencies.Either[float64]`** : un seul struct par valeur `{ Kind EitherKind; Information string; Value float64 }`. Les parenthèses de type sont déballées. L'ordre des membres de l'union est sans effet. |
| P1 valeur | `DEither.success(x)` donne `EitherSuccessOf[float64](x)`, avec `Kind = EitherKindSuccess` et `Information = "success"`. `DEither.fail()` donne `EitherFailOf[float64]()`. |
| P2 premier niveau | `var Sourced_result shard_dependencies.Either[float64]` au niveau du package, et `Sourced_result = …` dans `func init()`. |
| P2 dans une fonction | `sum := …` (déclaration locale). |
| P3 | `if cond { … } else { … }`. Les instructions préparatoires (`before`) de la condition sont placées avant le `if`. Celles d'un `else if` vont **dans** le `else`, sinon l'appel serait évalué à tort (variante `01-else-if`). |
| P4 | `DEither.isRight(e)` donne `e.IsRight()`, soit `Kind == Right \|\| Kind == Success`, inliné par Go. |
| P5 | `DCommon.print(v)` donne `shard_dependencies.Print[T](v)` : un formateur `util.inspect` qui renvoie son entrée. Les Either exposent leurs clés DuploJS ordonnées via `InspectEntries()`. |

## Justification

- **Représentation des Either (ADR-1)** **[observé]** dans [ADR-1](../decisions/ADR-1-either.md) §3 et §4 : le struct par valeur `Either[V]` ne fait **aucune allocation**, alors que l'interface (option B) et `Value any` (option C) allouent à chaque retour non inliné. Il est **5 à 8 fois plus rapide** sur 1000 valeurs (`Map1000` : environ 20 µs contre 150 à 164 µs ; 32 Ko contre 57 à 80 Ko). Un seul type Go couvre `Success<T>`, `Fail` et leurs unions : aucune conversion n'est nécessaire au `return` dans l'exercice 01.
- **`Kind` à 4 valeurs plutôt qu'un booléen :** `print` doit distinguer `success`/`right` et `fail`/`left`, puisque les clés affichées diffèrent. Un `uint8` ne coûte rien de plus qu'un `bool` dans le struct.
- **Variable de package plutôt que `:=` au premier niveau :**
  1. Une `const` de module TypeScript est visible des fonctions du fichier (variante `01-const-used-by-function`) ; une variable locale à `init()` ne le serait pas.
  2. Une variable de package inutilisée n'est **pas** une erreur en Go, contrairement à une variable locale (défaut D6).
  3. Le code de premier niveau reste dans `init()` : l'ordre d'exécution des modules est conservé, puisque Go initialise les packages importés avant le package importateur.
- **`any` limité à l'affichage :** `InspectEntry.Value any` sert uniquement au chemin de `print`, qui est limité par les entrées-sorties. Les calculs (`add`, `isRight`) n'utilisent jamais `any`. **[à vérifier]** : mesurer le coût de `print` n'apporterait rien au comportement, et ce n'est pas prévu.
- **Reconnaissance par symbole :** `isRight` et `print` sont identifiés en résolvant le symbole jusqu'à `@duplojs/lang` (`dist/either/`, `dist/common/`), jamais par leur nom. La variante `01-alias` le vérifie.

## Limites

> **À compléter après merge** avec les limites remontées par P2, P3 et P4.

Limites déjà identifiées **[à vérifier]** :
- Unions qui contiennent un membre **non Either** (`number[] | Fail`) : hors ADR-1, l'ADR-2 est prévue au Sprint 2.
- Unions dont les deux côtés portent des types différents : représentation A' `Either2[L, R]`, prévue à l'exercice 09.
- `print` avec un 2e argument (`"warn"`, `{ depth }`, `{ columns }`) : non pris en charge.
- Formes de `util.inspect` non couvertes par les variantes : objets imbriqués au-delà de la profondeur 2, `Map`/`Set`, tableaux de plus de 6 éléments sur plusieurs lignes, chaînes contenant des `'`.
- Déstructuration dans un `const` (`const [a, b] = …`) : hors périmètre de l'exercice 01.
