# Exercice 02 : fonction passée en argument (`whenIsRight` + `coalescing`)

> Légende : **[observé]** = exécuté, la preuve est citée ; **[à vérifier]** = raisonnement ou attente non encore confirmés par une exécution.
> 🚧 **Sprint 2 en cours** : la stratégie est décidée (PLAN §0.5, ADR-2 et ADR-3). Les sections « Go produit » et « Après le Sprint 2 » seront remplies après les merges.

## Problèmes étudiés

Source : [`projects/02`](../../projects/02). La fonction `add` est celle de l'exercice 01 : `Success<number> | Fail`.

```ts
const result = add(1, 2);
if (DEither.isRight(result)) { DCommon.print(result); }

const newResult = DEither.whenIsRight(result, DArray.coalescing);
DCommon.print(newResult);
```

| # | Problème | Détail |
|---|---|---|
| P1 | **Transmettre une fonction en argument** | `DArray.coalescing` est une fonction **générique** de DuploJS (`<V>(v: V) => Coalescing<V>`), passée sans être appelée. En Go, une fonction générique ne peut pas être une valeur sans être instanciée (défaut D1). |
| P2 | **Appliquer la fonction seulement au cas Right** | `whenIsRight` appelle le callback avec la valeur **déballée** si l'entrée est un Right ; sinon, il renvoie l'entrée **inchangée**, sans appeler le callback (sémantique vérifiée, `docs/duplojs-semantics.md`). |
| P3 | **Représenter le résultat** | Le résultat du callback n'est **pas ré-enveloppé**. Le type est donc **`Fail \| readonly [number]`** **[observé]** (type mesuré en provoquant une erreur de typage) : une union qui mêle un Either et une **valeur nue**. |
| P4 | **Afficher une valeur nue** | `print(newResult)` affiche `[ 3 ]` (un tableau, pas un objet Either) dans le cas Right, et l'objet `Fail` dans l'autre cas. |

Sortie de référence **[observé]** :
```
{
  '@duplojs/lang/kind/@DuplojsLangEither/right': null,
  '@duplojs/lang/kind/@DuplojsLangEither/information': 'success',
  '@duplojs/lang/kind/@DuplojsLangEither/value': 3,
  '@duplojs/lang/kind/@DuplojsLangEither/success': null
```

## Stratégie

Décisions du point d'équipe (PLAN §0.5) :

| Problème | Traduction Go visée | Responsable |
|---|---|---|
| P1 | Appel **direct** de `coalescing` dans le code inliné de `whenIsRight`, **inliné statiquement** selon le type de l'argument : `[]float64{v}`, ou `v` si c'est déjà un tableau. Passé ailleurs en valeur, il devient un **`func` literal instancié** (`createFunctionValue`), jamais une fonction générique nue. | P2 (coalescing), P3 (`createFunctionValue`) |
| P2 | **`whenIsRight` inliné** : `var r T ; if e.IsRight() { r = coerce(f(e.Value)) } else { r = coerce(e) }`. Le callback n'est évalué **que** dans la branche Right. | P3 |
| P3 | **ADR-2** : `Fail \| readonly [number]` devient **`Either[[]float64]`** avec une 5e forme **`EitherKindPlain`** (valeur nue). La valeur du callback est enveloppée par `EitherPlainOf[[]float64](…)`, et le `Fail` est converti par `EitherRetype[[]float64, float64](e)` (permis parce que `Fail` ne porte pas de valeur). Les tuples homogènes deviennent des slices `[]T`. | P4 |
| P4 | `Print` teste d'abord `InspectPlain()`, puis affiche la **valeur nue** (`[ 3 ]`) pour la forme `Plain`. | P3 (formateur), P4 (méthode) |

Go visé (schéma, **[à vérifier]** après merge) :
```go
var Sourced_newResult shard_dependencies.Either[[]float64]
// dans init() :
var Generated_r shard_dependencies.Either[[]float64]
if Sourced_result.IsRight() {
	Generated_r = shard_dependencies.EitherPlainOf[[]float64]([]float64{Sourced_result.Value})
} else {
	Generated_r = shard_dependencies.EitherRetype[[]float64, float64](Sourced_result)
}
Sourced_newResult = Generated_r
```

## Justification

- **Forme `Plain` plutôt qu'une interface ou `any` :** c'est le **même struct par valeur** que l'ADR-1 (`Kind`, `Information`, `Value`), donc **aucune allocation** par valeur. L'ADR-1 a mesuré 0 allocation contre 1 par retour pour une interface, et un temps 5 à 8 fois moindre sur 1000 valeurs **[observé, ADR-1]**. `Plain` ne fait qu'ajouter une valeur au discriminant `Kind` (un `uint8`).
- **`IsRight()` faux pour `Plain` :** c'est fidèle à DuploJS, où `isRight` teste la **présence des clés** de l'objet. Une valeur nue n'est donc ni Right ni Left. La variante `03-pipe-two-steps` en dépend : un 2e `whenIsRight` reçoit `6` (nu) et le renvoie **inchangé** **[observé côté TS]**.
- **Inlinage de `whenIsRight` :** il n'y a ni appel indirect ni closure, et le type de chaque branche est connu à la transpilation. Le callback n'est évalué que si la branche Right est prise, ce qui préserve la sémantique (variante `02-left-input`).
- **`coalescing` inliné statiquement :** le type de l'argument est connu à la transpilation (tableau ou non). Le test `instanceof Array` de l'exécution disparaît.
- **Slices pour les tuples :** `coalescing` renvoie un tuple ou un tableau selon l'entrée. Les deux doivent avoir **le même type Go** pour être regroupés dans une même union. Le coût est un slice alloué ; l'optimisation `[N]T` est reportée à l'ex. 08.

## Limites

**[à vérifier]**, à confirmer après implémentation :
- Callback qui renvoie un Either dont les variantes gauches **portent une valeur** d'un autre type que celles de l'entrée : la conversion `EitherRetype` n'est pas permise, on obtient `notSupport` (repli de l'ADR-1).
- Unions de **plusieurs types nus différents** (par exemple `number | string`) : union fermée générée ou `any`, non implémentés au Sprint 2.
- Tuples **hétérogènes** (`[string, number]`) : `notSupport`, prévu à l'ex. 08.
- Fonction **générique utilisateur** passée en valeur : non couverte par une variante.
